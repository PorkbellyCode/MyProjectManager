## 한 줄 요약
운영 중인 서비스의 요청 티켓을 **AI 에이전트가 먼저 인터뷰·검토**해서 중복·해소 가능한 건은 요청자 스스로 거르게 하고, 나머지는 정보를 채워 담당 대상(사람/그룹)을 추천하는 도구. **AI는 제안만, 결정은 사람이.** 형준의 CRDD 확장판이며 **포트폴리오용 사이드 프로젝트**(주목표: AI 에이전트 설계 역량, 부목표: 협업 흐름 이해).

## 핵심 결정 요약
- **스택**: Next.js 단일 앱, TypeScript, Neon(Postgres)+Drizzle, Vercel 배포, Vercel AI SDK로 직접 구성, 기본 제공자 Anthropic(교체 가능: Claude/ChatGPT/Gemini), Better Auth(조직=프로젝트), Tiptap(마크다운 저장, 스크린샷 붙여넣기·드롭), shadcn/ui+Tailwind(정형화 탈피), TanStack Table, nuqs, cmdk, Motion, sonner, t3-env, react-hook-form+zod, Langfuse, DB 기반 작업 큐, Playwright E2E + Vitest, pnpm.
- **AI 원칙**(메인 3.1): 제안만 하고 값을 바꾸지 않음, 근거(티켓 링크·커밋·도메인 지식) 없으면 제안 안 함, 모르면 넘어감. 자동 철회·AI 긴급도 조정·확신도 기준값·부하 기반 자동 배정은 없음.
- **AI 구조**: 하이브리드. 바깥 단계(중복 확인 → 해소 확인 → 인터뷰 → 대상 추천 → 정리본)는 코드로 고정. 인터뷰 안에서만 1차는 리드 혼자, 2차부터 리드가 분야 에이전트(최대 3개)를 병렬 호출. 모든 판단은 근거·지시사항 버전과 함께 `ai_judgments`에 기록.
- **요청자 흐름**: 검토 요청 → 중복 후보면 "같은 건이에요"(기존 티켓 댓글로 합류·구독) / "다른 건이에요" → 근거 있는 해소 제안이면 "해결됐어요 / 인터뷰 계속 / 그대로 제출" → 선택형 질문 최대 2라운드×3개 → AI 추천 대상을 확인·변경해 제출. 검토 중 화면을 떠나도 되고 준비되면 앱 안 알림. 긴급도는 요청자 값 고정(AI는 참고 문구만).
- **배정(뷔페 방식)**: 대상은 사람 또는 그룹(영역 개념을 그룹으로 통합). 사람 → 배정됨 → 수락, 그룹 → 그룹 큐에서 가져가기, 없음 → 리드 큐. 이관은 사유와 함께(반려 대체).
- **종결**: 처리 완료 → 확인 대기 → 요청자 "고쳐졌어요"(종결) / "아직이에요"(재오픈). 확인 대기는 자동 종결 안 함. 종결 사유: 해결 확인 / 안 하기로 함(**리드만**) / 중복 / 요청자 회수 / 기타.
- **단계**: 1차 기준선(리드 혼자) → 2차 멀티 에이전트 + 평가 세트 비교 리포트("이만큼 나아졌다") → 3차 프로젝트별 키·추천 구성·재실행·실시간·DM·대시보드·가이드 → 4차 Slack/Notion/Jira·MCP 서버·보안 모드.
- **에이전트 역량 증명**(메인 6.13): 기준선→개선 서사, 프롬프트 회귀 테스트(CI), 제공자 비교, 판단 기록 재생 화면, 제작 과정 기록, MCP 서버.
- **AI 키**: 3차에 프로젝트별 등록(AES-256-GCM, 끝 4자리 표시). 1·2차는 시연 프로젝트만 서버 키.
- **화면**: 로그인/초대 수락, 프로젝트 목록/새 프로젝트, 티켓(목록|상세 3단), 레포 개요(별도 진입점), 관리자(도메인 지식/에이전트/설정), 알림.
- **보안 모드**: 지금은 갈아끼울 지점만 분리(RepoSource, 모델 레지스트리, BlobStore). 4차 이후 로컬 스캔 CLI, 자체 설치형. Electron 제외.
